What we're not building

Cloud-side state (Files / Assistants / Threads / Vector Stores / Batch / Moderation / Realtime / DALL-E / built-in cloud tools) is deliberately out of scope. eVi is local-first; pushing user data into a vendor's cloud-state surface defeats that.

If a user wants any of those, they can already point eVi at a cloud-OpenAI-compatible endpoint via the openai_compat backend. That gives access to the underlying provider's hosted features without needing us to re-implement them.
