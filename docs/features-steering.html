Steering a running turn

Overview

You can type while eVi is still working. In the web and desktop app a message sent during a turn is queued and applied at the turn's next step, after the tool eVi is running finishes, instead of interrupting the work or being lost behind a disabled Send button. "Correct it while it works" replaces "wait, or stop and start over".

  • While a turn runs, the Send button reads Queue.
  • Your message appears in the conversation at once, tagged queued — applies at the next step, and the tag changes to applied when it lands.
  • Nothing is lost. If the turn finishes before there is a next step (the model just answered, or the turn ended on an error or its step limit), the queued message is sent as a normal message instead.

How it works

A turn is a loop: the model replies, eVi runs the tools it asked for, and the model sees the results in the next round. A steering message waits in a queue on the session's agent. At the top of each round, before the model is called again, eVi appends everything queued to the conversation as your messages, writes them to the transcript and emits a Steering event (applied: true) on the turn's event stream; the model reads them together with the tool results.

When the turn ends, anything still queued is handed back as Steering events with applied: false — always before the turn's closing Done (or Error) event, so Done is the last frame — and the web UI resends each one as a normal message. A re-roll hands queued follow-ups back the same way.

Steering never cancels anything. A long tool (a big download, a slow test run) finishes first; the correction applies right after it. To end the turn instead, stop it (Stopping a turn).

Usage

Web and desktop

Type and press Enter (or click Queue) while a turn is running. Use it for corrections ("not that file, the one in src/"), extra constraints ("and keep the public API unchanged") or answers to a question the model asked in passing.

API

POST /api/session/<session_id>/steer
Content-Type: application/json

{"text": "use the staging config instead"}
ResponseMeaning
{"queued": true, "pending": 1}Queued; applies at the next step (pending counts what is waiting)
{"queued": false, "reason": "not busy"}No turn is running: send it as a normal message (POST /api/chat)

An empty text is a 400. The Steering events arrive on the stream of the POST /api/chat request that runs the turn: {"kind": "Steering", "text": "...", "applied": true}.

Stopping a turn

A turn can be stopped from every surface. Whatever it was doing, it ends with Done reason interrupted, and the session stays usable:

  • A reply being streamed stops; its text so far is kept, marked as cut off.
  • Running commands (run_command, run_python, monitor) have their whole process tree killed, child processes included, and keep the output they had so far.
  • Calls that never ran, and a tool still running two seconds after the stop (one that ignores it is left behind), are answered (cancelled), so the history stays valid for the next message. The stop hook fires.
  • A permission question the turn is waiting on is answered no, and nothing more is asked.

Web and desktop

While a turn you started from this page runs (a message or a re-roll), a red Stop button shows next to Send. It reads Stopping… until the turn has ended, then goes away; you can send your next message at once.

POST /api/session/<session_id>/cancel
ResponseMeaning
{"cancelled": true, "busy": false}Stopped; the session is free for the next message
{"cancelled": false, "reason": "not busy", "busy": false}No turn was running

It answers once the session is free again: normally well under a second, within a few seconds when a tool ignores the stop. Only your own live sessions can be stopped; any other id is a 404. The stopped turn's own POST /api/chat stream ends with {"kind": "Done", "reason": "interrupted"}.

Terminal (evi chat)

Press Ctrl+C while a turn runs to stop it; the REPL is back at its prompt with the session intact. An open permission prompt is answered no. A second Ctrl+C within two seconds quits eVi.

evi run

Ctrl+C (or a SIGINT from a script or CI runner) stops the turn and still reports a result: --format json prints the usual object with "stop_reason": "interrupted" (a run that finished says why it stopped, e.g. "stop"), text mode prints what streamed before it plus a note on stderr, and the exit code is 130. A second Ctrl+C stops waiting for the turn to wind down.

Notes / limits

  • Steering is web and desktop only. The terminal REPL and evi run have no steering (stopping works everywhere).
  • Applied between steps, not mid-step. A model that is still writing its answer finishes it first; if it then makes no tool call the turn ends, and your message is sent as the next turn.
  • Text only. A message with an attached image, or a /command, typed during a turn is not queued as steering.
